## الصفحات

- **الرئيسية:** مبيعات اليوم والشهر، الربح، الديون، تنبيهات (نسخة احتياطية قديمة، كميات سالبة…)، ورسم بياني.
- **البيع:** سلة محفوظة على الجهاز، نقدي أو آجل على زبون، خصم بمبلغ أو بنسبة، وطباعة A4 أو إيصال حراري 80mm. الاختصار **F9** يُتم البيع.
- **الفواتير:** بحث بالفترة أو الزبون أو الرقم، **مرتجع جزئي**، وإلغاء كامل.
- **الزبائن والديون:** كشف حساب لكل زبون، استلام دفعة مع سند قبض، رصيد سابق من الدفتر، وتذكير واتساب.
- **المنتجات:** فلاتر (بدون سعر، بدون باركود، راكد…)، تحديد متعدد، **تعديل جماعي مع تراجع**، وتصدير Excel مخصص.
- **المشتريات:** فاتورة شراء تزيد الكمية وتحسب **متوسط التكلفة** تلقائياً وتحدّث رصيد المورد.
- **حركة المخزون:** سجل لكل دخول وخروج لأي قطعة، ولا يمكن تعديله.
- **الجرد:** تعدّ بالمسح أو الكتابة من أكثر من جهاز معاً، ثم تطبّق الفروقات.
- **التقارير:** المبيعات والربح والأكثر مبيعاً، حسب القسم أو الماركة، قيمة المخزون، الراكد، وقائمة إعادة الطلب جاهزة للمورد.
- **تنظيف البيانات:** توحيد الماركات (FAG / Fag)، توحيد كتابة الأسماء، دمج المكرر، وتوليد باركود للناقص.
- **Excel:** صدّر المنتجات مع عمود "المعرّف"، عدّل الأسعار في Excel، ثم استورد الملف فيتحدث كل منتج.
- **بحث سريع:** Ctrl+K من أي صفحة.

## تحديث v3.1 — الحماية والسرعة

- **منع تكرار القطعة:** عند إدخال منتج مسجل مسبقاً (نفس الباركود، رقم القطعة، أو اسم قريب) يظهر المنتج الموجود مع **مكانه (المخزن والرف) وكميته وباركوده**، وزر لإضافة الكمية له بدل إنشاء نسخة ثانية. الباركود المكرر ممنوع (يمكن السماح به من الإعدادات).
- **أرقام فواتير متسلسلة:** INV-00001، QT-00001، PUR-00001 (عداد على السيرفر لا يمكن إرجاعه أو القفز به).
- **التحقق من الكمية على السيرفر قبل البيع** + خيار "منع البيع بكمية أكبر من المتوفر".
- **الموظف لا يستطيع تغيير سعر الشراء** (محمي بقواعد السيرفر، ليس فقط بالواجهة).
- **مزامنة جزئية للمنتجات:** الجهاز يقرأ من السيرفر فقط ما تغيّر منذ آخر مرة (أسرع وأقل استهلاكاً)، ومزامنة كاملة أسبوعياً.
- **خروج تلقائي** بعد مدة عدم استخدام (من الإعدادات).
- **تنبيه ساعة الجهاز** إذا كان وقت الجهاز غير مضبوط (يؤثر على تواريخ الفواتير).
- **تسجيل أخطاء الأجهزة** في سجل العمليات ← "أخطاء الأجهزة".
- **أرشفة السجل** الأقدم من سنة (للمالك).
- **كشف الحساب:** زر "تحميل حركات أقدم".
- **الفواتير وعروض الأسعار:** شعار المحل + المبلغ كتابةً (التفقيط).
- **موقع الزبائن:** رابط خاص لكل قطعة + زر مشاركة، وصفحات ثابتة `/p/<id>` تظهر في Google ومعاينة واتساب، مع `sitemap.xml`.
  - الصفحات الثابتة تُولّد عند كل نشر (`node build.js`) من الكتالوج العام — أعد النشر بعد تغييرات كبيرة بالأسعار حتى تتحدث معاينات الروابط.

## تفعيل الخدمات الإضافية (الكود جاهز — فقط فعّلها)

> انشر دائماً بـ `--only` حتى لا يحاول النشر خدمة غير مفعّلة بعد.

### 1) خطة Blaze — الصور، النسخ التلقائي، إضافة الموظفين من السيرفر
1. Firebase Console ← ⚙️ Usage and billing ← **Upgrade to Blaze**. ضع **تنبيه ميزانية** (Budget alert) بـ 5$ مثلاً حتى لا تتفاجأ — الاستهلاك المتوقع لمحل واحد قريب من الصفر.
2. Console ← **Storage** ← Get started (اختر نفس المنطقة).
3. انشر: `firebase deploy --only storage,functions --project mohammad-jasm`
4. في لوحة الإدارة ← الإعدادات ← "خدمات خطة Blaze" ← **🧪 اختبار وتفعيل تخزين الصور**، ثم **🚚 نقل الصور القديمة** (خذ نسخة احتياطية مع الصور قبلها).
5. بعدها يعمل تلقائياً:
   - **نسخة احتياطية يومية** الساعة 3 فجراً (بتوقيت بغداد) في Storage ← `backups/`، تُحفظ آخر 30 يوماً.
   - **إضافة/حذف الموظفين من السيرفر** (صفحة المستخدمين). بعد التأكد أنها تعمل: Authentication ← Settings ← User actions ← ألغِ **Enable create (sign-up)** — هكذا لا أحد يستطيع إنشاء حساب بنفسه أبداً.

### 2) App Check — يرفض أي طلب لا يأتي من موقعك
1. Console ← **App Check** ← Apps ← سجّل تطبيق الويب بـ **reCAPTCHA v3** (يعطيك "site key"؛ أضف النطاقين `mohammad-jasm.web.app` و `mohammad-jasm-admin.web.app`).
2. ضع المفتاح في `src/common/firebase.js` ← `APP_CHECK_SITE_KEY`، ثم انشر `hosting`.
3. انتظر يومين وراقب App Check ← Metrics: لازم تكون الطلبات **Verified**.
4. بعدها اضغط **Enforce** لـ Firestore و Storage، وفي `functions/index.js` اجعل `ENFORCE_APP_CHECK = true` وانشر `functions`.
   - ⚠️ لا تضغط Enforce قبل التأكد من الخطوة 3، وإلا الأجهزة القديمة تتوقف.

### 3) GitHub — حفظ كل نسخة من الكود + اختبار تلقائي
1. ثبّت Git: https://git-scm.com/download/win وأنشئ مستودعاً **خاصاً (Private)** على GitHub.
2. في مجلد المشروع:
   ```
   git init -b main
   git add .
   git commit -m "نظام المخزن v3.1"
   git remote add origin https://github.com/<اسمك>/<المستودع>.git
   git push -u origin main
   ```
   ملف `.gitignore` يمنع رفع النسخ الاحتياطية وكلمات المرور.
3. **CI** (`.github/workflows/ci.yml`): مع كل رفع يفحص الملفات ويشغّل اختبارات الحماية (قواعد قاعدة البيانات + التخزين) تلقائياً.
4. **النشر من GitHub** (`deploy.yml`، يدوي فقط): Google Cloud Console ← IAM ← Service Accounts ← أنشئ حساباً بصلاحية *Firebase Admin* ← Keys ← JSON. ضع محتواه في GitHub ← Settings ← Secrets ← Actions باسم `FIREBASE_SERVICE_ACCOUNT`. ثم Actions ← Deploy ← Run workflow. لا ينشر إذا فشل أي اختبار.

## ⚠️ العراق وخطة Blaze

Google لا يقبل العراق كدولة لحساب الدفع، لذلك **لا تُستخدم خطة Blaze**. لا تختر دولة أخرى بعنوان غير حقيقي (قد يُعلَّق الحساب). البدائل المجانية:

| الميزة | الحل بدون Blaze |
|---|---|
| الصور | تبقى داخل قاعدة البيانات (مضغوطة) — الحصة المجانية 1GB تكفي آلاف الصور |
| النسخة الاحتياطية اليومية | `.github/workflows/backup.yml` — يومياً الساعة 3 فجراً، تُحفظ 30 يوماً في GitHub |
| App Check | يعمل على الخطة المجانية |
| إضافة الموظفين | كما هي — أي حساب ينشئه شخص بنفسه يبقى "بانتظار الموافقة" ولا يرى شيئاً |

### تشغيل النسخة اليومية عبر GitHub
1. اتبع خطوات GitHub أعلاه (مستودع **خاص**) وأضف السر `FIREBASE_SERVICE_ACCOUNT`.
   - إنشاء حساب الخدمة مجاني ولا يحتاج Blaze: https://console.cloud.google.com/iam-admin/serviceaccounts?project=mohammad-jasm ← Create ← دور **Cloud Datastore User** يكفي للنسخ (و *Firebase Admin* إذا أردت النشر من GitHub) ← Keys ← Add key ← JSON.
   - ملف المفتاح سرّي جداً: ضعه في GitHub Secrets فقط ثم احذفه من جهازك.
2. Actions ← **Daily backup** ← Run workflow (للتجربة الأولى).
3. التحميل: Actions ← Daily backup ← آخر تشغيل ← Artifacts ← `inventory-backup`. يُسترجع من لوحة الإدارة ← النسخ الاحتياطي.
4. صفحة "النسخ الاحتياطي" تعرض "آخر نسخة تلقائية" — إذا توقفت لأكثر من يومين راجع GitHub.

ملفات الدوال السحابية (`functions/`) و `storage.rules` باقية جاهزة إذا صار Blaze متاحاً مستقبلاً.

## 🤖 التعبئة الذكية بالكاميرا (Google Gemini — مجاني)
- **التفعيل:** https://aistudio.google.com/apikey ← **Create API key** ← انسخه ← لوحة الإدارة ← الإعدادات ← التعبئة الذكية ← الصقه ← حفظ. مجاني ومتاح في العراق.
  - المفتاح لا يوضع في كود الموقع؛ يُحفظ في settings/ai ولا يقرأه إلا الموظفون المسجلون، ولا يدخل ملفات النسخ الاحتياطي.
  - Firebase AI Logic (مفعّل أيضاً) سيتطلب App Check بـ reCAPTCHA Enterprise من 2 نوفمبر 2026، وهذا يحتاج حساب Google Cloud غير متاح للعراق — لذلك الاعتماد على مفتاح AI Studio.
- الاستخدام: المنتجات ← **🤖 إضافة بالكاميرا**، أو زر **تعبئة ذكية** داخل أي منتج. صوّر الملصق/العلبة/النقش (حتى 3 صور) أو الصق نصاً ← راجع الحقول المقترحة ← تطبيق ← حفظ.
- لا يُحفظ شيء تلقائياً، وكشف المكرر يعمل بعد التعبئة مباشرة.
- الإعدادات ← "التعبئة الذكية": تشغيل/إيقاف، اختيار النموذج، زر اختبار.
- الحد المجاني يكفي عشرات القطع يومياً؛ إذا ظهر "وصلت للحد" انتظر دقيقة.
- لا تصوّر مستندات فيها معلومات شخصية — الصور تُرسل إلى Google للتحليل.
- 💰 **الأسعار التقريبية:** بعد التحليل يبحث Gemini في Google عن سعر القطعة في السوق العراقية (مدى السعر، الشائع، أصلي/تجاري، المصادر) ويعرض أسعار القطع المشابهة في محلك. إذا انتهى حد البحث المجاني يعطي تقديراً بدون بحث ويوضح ذلك.
